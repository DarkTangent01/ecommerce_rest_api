**How "verified" was established**
- Every finding has a regression test.
- Every new or extended test file was also run against the **pre-fix** `src/` (HEAD, in three batches). Each file had failing tests there: **54 of the 104** tests in those files fail on the old code. ## 3. Behaviour and API changes (compatibility)

| Change | Who is affected |
|---|---|
| Refund state lives in `refundStatus`; `POST /orders/:id/refund` no longer sets `status: refund_requested`, and only accepts delivered orders within the window. Paid cancellations return `refundStatus: requested`. | Clients reading `status === 'refund_requested'`. The Angular app was updated in this change. |
| `GET /seller/dashboard` → `recentOrders` are DTOs (`_id, status, paymentStatus, createdAt, items, sellerSubtotal, shippingAddress?`). | Seller dashboard clients; the Angular type was updated. |
| `X-Request-Id` in responses is always server-generated; client ids appear as `X-Correlation-Id`. | Log/trace tooling that relied on the echo. |
| Registration requires an existing, active, open tenant (except the implicit default). | Deployments with tenants that exist only implicitly. See the checklist. |
| Webhooks: the provider must be in `WEBHOOK_PROVIDERS` and match the tenant's `config.paymentProvider`. | Payment integrations using a provider name other than `manual`. |
| Shipments are per seller; the order status is derived. | Seller and admin shipment flows (same endpoint and body). |
| Service tokens need a `tenant` claim. | Internal services calling `/internal/events`. |
| `/openapi.json` is admin-only in production by default. | Anyone fetching the spec in production anonymously. |
| SSE: max 3 streams per user by default, streams end after 1 h (`event: expired`; clients reconnect via `retry: 5000`). | SSE clients. |
| `<` and `>` are no longer stripped from input. | None for the Angular app; any non-escaping renderer must encode. |

## 5. Remaining risks, by priority

1. **Multi-instance deployments (I-1, SEC-06, SEC-01):** rate limits, SSE caps and the checkout lock are per process. Add Redis-backed stores before running more than one instance.
2. **Refund operations (SEC-05):** refunds are requested and completed by webhook, but there is no admin approve/reject endpoint and no automatic provider call. Operations must act on `refund.requested` events.
3. **Event re-dispatch (SEC-12):** events persist as `pending`, but nothing re-queues them after a dispatch failure.
4. **Registration enumeration (SEC-09):** register still reveals whether an email exists. It needs an email-verification flow to remove.
5. **Shared webhook secret (SEC-11):** one secret for all tenants and providers.
6. **Tenant onboarding policy (SEC-07):** invitation or hostname-based sign-up is a product decision still open.
